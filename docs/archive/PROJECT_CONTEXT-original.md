# SSAFY 3차 AI × OSS 프로젝트 기획 컨텍스트

> Codex 전달용 · 2026-10-10 기준 · **프로젝트 주제는 아직 미확정**

## 1. 목적과 원칙

- 7인 팀의 SSAFY 3차 프로젝트 주제 선정. AI 기술과 오픈소스(OSS)를 활용해 실제 작동하는 재미있고 유용한 프로그램을 만든다.
- 첫 데모를 작게 구현한 뒤 **문제 정의 → 후보 기술 비교 → 연결 → 측정 → 개선 → 재검증**을 반복한다.
- AI 모델을 직접 학습하는 것은 필수가 아니다. 적절한 모델을 선택하고 전처리·검색·프롬프트·추론·도구 연결 등의 파이프라인을 개선해도 AI 엔지니어링 역량이다. 다만 모델 자체 개선과 활용 시스템 개선은 명확히 구분한다.
- 행동 트리, 물리 엔진, RAG, 지식 그래프가 모두 AI 모델인 것은 아니다. AI가 꼭 필요한 부분을 설명한다.
- OSS는 라이선스·유지관리 상태·재현성·기여 가능성을 확인한다. PR은 머지되지 않아도 별도 브랜치·포크에서 개발을 지속할 수 있다.
- 코드를 바로 시작하지 말고 오피스아워로 검토하고 결정 내용을 Markdown에 기록하며 단계적으로 진행한다.

## 6. Codex 작업 지침 (읽은 후 실행)

- 이 문서는 **과거 대화의 결정사항과 아이디어를 정리한 컨텍스트**이며, 세부 구현이 확정된 사양서는 아니다.
- 주제 미확정 단계에서는 **코드를 무작정 생성하지 말 것**. 먼저 각 후보의 MVP, AI의 필수 역할, OSS 비교, 주요 리스크, 측정 가능한 개선 지표를 논의한다.
- 오피스아워에서는 가정·제약·대안을 검토하고 결론을 문서화한다. 선정 후 `docs/decision-log.md`, `docs/roadmap.md`, `docs/experiments.md`를 운영한다.
- 매 단계는 **작동 → 측정 → 문제 분석 → 개선 → 재측정**의 형식으로 기록한다. 기술 선택은 최신 릴리스·라이선스·하드웨어 요구 사항을 다시 확인한다.
- 사용자는 설명이 어렵지 않고 실용적이며, 평가·데모·포트폴리오에서 설명 가능한 프로젝트를 선호한다.

> `PROJECT_CONTEXT.md`를 먼저 전부 읽어줘. 아직 주제는 확정하지 않았다. 8개 후보를 현재 기준으로 이해하고, AI가 반드시 필요한 핵심 기능과 모델/OSS 선택, 최소 데모, 가장 큰 불확실성, 성능 개선 실험을 비교해줘. 바로 구현하지 말고 오피스아워 방식으로 설계 방향을 검토하자. 논의가 끝나면 결정 사항과 열린 질문을 Markdown으로 기록해줘.
